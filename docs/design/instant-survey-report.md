# Instant survey report

Implemented locally, 12 October 2026. This source change is not a published release.

## Purpose

Help someone turn a spreadsheet of survey responses into editable tables and
graphs without setting up each analysis separately. Routine reports should
take one action after import and review. Ambiguous data must receive an explicit
decision rather than an unsupported statistical interpretation. All existing
manual analysis and presentation controls remain available.

The first version produces descriptive reports from a selected Excel worksheet
or CSV/TSV table. It does not select inferential tests, score questionnaires,
infer repeated measurements, apply survey weights or make causal claims.

## User journey

1. Choose **Instant survey report** from Data or Analyse. With no data loaded,
   use the existing spreadsheet import and preview flow. With data loaded, use
   the current dataset after resolving pending edits through existing guards.
2. Show a scrollable review of variables: include/exclude, proposed reporting
   role, valid/missing counts and relevant warnings. Suggestions are labelled
   as suggestions. Every included variable must have a supported role.
3. Offer **Create report** when the review is valid. Generate the selected
   summaries in a cancellable background operation. Publish the complete set
   of saved analyses together and navigate to Results.
4. Let the user edit each analysis and figure through existing controls. Offer
   **Export survey report**, using only the runs generated by this operation.
   Ask for the destination through the existing export dialog.

Import remains subject to worksheet selection, formula/stored-value decisions,
numeric precision warnings and existing project-replacement safeguards.

## Reporting rules

- **Categories:** frequency tables with counts, percentages of all responses,
  percentages of valid responses and missing counts; an editable bar chart.
- **Numeric measure:** require numeric storage and explicit confirmation of
  this role, or existing Scale metadata. Produce valid/missing N, mean, sample
  standard deviation, minimum and maximum, plus a histogram with automatic
  bins. Existing boxplots can be chosen manually.
- **Exclude:** retain the variable in the dataset but omit it from this report.

Nominal metadata can suggest Categories. Ordinal metadata can suggest an exact
category frequency table, but does not establish a response order or justify a
mean. Unknown numeric columns require a role decision. Low distinct-value
counts may suggest Categories; they never establish measurement level.

Potential respondent IDs, names, email addresses, timestamps, free text and
high-cardinality columns default to excluded or unresolved. The review explains
why and allows explicit inclusion as Categories where appropriate. Header and
value heuristics are advisory and cannot guarantee detection of personal data.
All included columns remain visible in review before calculation.

Multiple-answer cells are flagged and remain unresolved unless the user chooses
to count each complete cell as one exact category. This version never guesses
delimiters or splits answers. Likert ordering and diverging charts require the
existing explicit scale confirmation; the automatic report uses ordinary
category bars. Empty/all-missing columns show their status without misleading
plots or numeric estimates. Report generation with no supported included
variables is blocked with a clear explanation.

Suggest Categories only for columns with at most 30 distinct nonmissing values.
Above that threshold, require explicit inclusion with a warning that the table
and chart may be difficult to read. Display lists through existing bounded
views; no categories may be silently dropped to make a chart fit.

## Data checking and preparation

The first version checks data quality and proposes preparation; it never
silently cleans the source. Report generation leaves dataset values, row count,
column definitions and revision unchanged.

The existing project stores typed imported values rather than the original
spreadsheet bytes. Keep the original spreadsheet file untouched; do not claim
that saving a Tessera project archives its exact workbook formatting or bytes.

Show empty cells and existing missing rules separately from candidate missing
tokens such as “N/A”. Whitespace/case variants, possible duplicate rows and
multiple-answer values are review findings, not errors to remove automatically.
Do not report an exact duplicate count unless the full bounded scan completes.

Use existing Prepare controls for any user-approved recoding. Their immutable
new-column operations and undo remain authoritative. Recheck the survey review
after a data revision changes. Do not replace the source file, discard rows,
fill missing responses, remove outliers or merge categories automatically.

## Ownership and persistence

Add one survey workflow module for a revision-bound review, checked column
roles, quality findings and generation of existing analysis requests. Extend
the existing job operation/output contract for a single report batch. The
desktop state/action layer owns guarded entry, draft invalidation, progress,
publication and selection of generated runs.

Use existing Frequencies, Describe and Histogram engines. Append their results
to an immutable candidate Project using its controlled budget-aware methods.
Only publish that candidate after every requested calculation succeeds and the
job token/data revision is still current. Cancellation, validation failure,
resource limits and stale results leave the original project unchanged.

Reuse existing result views, figure settings, report writer, escaping and atomic
file transactions. No new dependency, analysis-result type or project schema is
needed for this version. Accepted choices are captured in ordinary analysis
recipes; record a concise report-generation note through existing provenance.
The review itself is temporary. After reopening a project, generated results
and figures remain available through normal history/export; the temporary
batch export selection need not persist.

Charge review scans, temporary indexes, requests, candidate project storage and
all retained results to the existing ownership budgets before allocation.
Keep checks cancellable and lists virtualised. Do not place data scanning on
the UI thread. No network or external AI service is involved.

## Proof before completion

Write failing tests before implementation. Use synthetic fixtures rather than
private survey data.

- Unit: checked roles, categorical suggestions, identifier/free-text warnings,
  missing-token and label-variant findings, mixed types, empty data, all-missing
  columns, constant numbers, cardinality limits and multiple-answer handling.
- Numerical integration: independently expected counts and both percentage
  denominators; known numeric summaries and histogram totals; verify the batch
  matches equivalent manual engine requests, including unavailable estimates.
- Safety integration: exact dataset equality before/after, atomic batch
  publication, cancellation, stale jobs, revision changes, retained-storage
  limits and no accidental inclusion of previous runs in survey export.
- Persistence/export: save/reopen generated runs and edited figures; report
  escaping, missing/excluded information and correct selected-run output.
- Desktop workflow: import/review/generate/edit/export, pending edit guards,
  Guided and Advanced access, compact windows, keyboard navigation and clear
  error recovery. Perform a native macOS walkthrough.

Run applicable existing regression suites, formatting/lint checks and coverage;
retain at least the project's required 80% production coverage. Native checks
on other platforms and screen-reader acceptance must be reported separately
if unavailable. Source changes do not constitute a published release.

## Verification record — 12 October 2026

The full instrumented application suite passed 1,164 tests; the workbook suite
passed 18. Production line coverage was 88.63% on macOS ARM64, including desktop
code. Uncompiled platform-specific files are listed in the coverage summary.
The Python tooling suite passed 35 tests and project-schema checks passed 23.
Formatting and all-target Clippy checks passed, with existing unrelated warnings.
Independent correctness and security reviews found no actionable blockers.

A separate local macOS preview imported a synthetic eight-row Excel workbook
through the native picker and worksheet/stored-number review. Reporting-role
review required explicit numeric confirmation and resolution of multiple-answer
cells. Generation produced frequencies, descriptives and a histogram together.
Native results matched independently expected counts, percentage denominators,
mean and sample standard deviation. A bar-chart title was edited, saved and
verified after reopening. The exported survey report retained that title and
the expected numbers; all 64 imported cells and eight headers matched the saved
project. Excluded email responses did not appear in the report. Native pointer
access to manual analysis and keyboard access to review roles were checked.

Automated desktop checks cover both analysis modes, paging, a 640 × 440 window
and 1.5× zoom. Native compact resizing could not be confirmed through the
available controls. Native Windows/Linux and screen-reader acceptance remain
open; no claim of complete accessibility or cross-platform acceptance is made.

Survey value inspection and calculations run in cancellable jobs. Existing
sharing-aware memory admission/publication bookkeeping remains synchronous.
Measured debug examples with two million text cells took about 66–101 ms for
cold entry and 98–149 ms for admission; these are examples, not latency bounds.
Large histories or other data shapes may pause longer. Personal-data and
measurement suggestions remain advisory and require user review.

Local evidence is retained under `.build/instant-survey-verification`,
`.build/survey-coverage` and `.build/instant-survey-native`. The original workbook
was only read. This workflow neither silently cleans data nor chooses
inferential tests.
